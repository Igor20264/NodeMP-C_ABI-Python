# Python 3.14 и 3.15 для NodeMP

Языковой модуль сервера NodeMP. Кладётся в `modules/pyhost.dll` и регистрирует ресурсы `type = "python"`. Скрипт видит глобальный `node`. Это отдельный репозиторий от хоста MicroPython.

Модуль и интерпретатор должны быть одной версии: эта сборка под Python 3.14 линкуется с `python314.dll`, сборка под 3.15 — с `python315.dll`. `python314.dll` в `modules/` класть нельзя: сервер пытается загрузить каждый DLL оттуда как модуль и отказывается, потому что у интерпретатора нет `node_plugin_abi`. Интерпретатор остаётся в своём каталоге, а перед запуском сервера задаётся `NODEMP_PYTHONHOME`.

Полный список имён — в [API.md](API.md). Заголовок SDK, по которому собран хост, лежит в `sdk/node.h` (ABI 2.8). Сервер 1.12.0 говорит на ABI 2.7, поэтому в логе будет `NEWER SDK (2.8 vs 2.7)`. Функции только из 2.8 при вызове возвращают ошибку.

Сервер по-прежнему вызывает все колбэки на одном worker-потоке. Долгая работа туда не ставится.

## Отдельное ядро

`submit_job` сервера кладёт работу в общий пул. Поток из этого пула операционная система переносит с ядра на ядро, и он делит ядра с сетью и worker-ом.

Хост заводит свой поток, core lane:

- Поток привязан к одному логическому процессору. По умолчанию это последний. `NODEMP_PYTHON_CORE=3` выбирает другой, `off` оставляет планировщику.
- Пока `NODEMP_PYTHON_RESERVE` не равен `0`, у остальных потоков процесса этот процессор снимается с маски affinity. Новые потоки сервер создаёт уже после старта, поэтому хост повторяет обход раз в пять секунд. Поток, у которого этот процессор единственный, не трогается.
- На macOS система не отдаёт ядро в исключительное пользование. Поток получает только метку affinity.
- Очередь одна. Задачи не разъезжаются по остальным ядрам.
- Поток спит, пока очередь пуста. Ядро занято, только когда задача выполняется.
- `done(result, error)` возвращается на worker через `set_timeout`. Из самой задачи этот callback ждать нельзя: он вызовется после её возврата.

```python
def crunch(n):
    return n * (n + 1) // 2

def show(result, error):
    node.log_info(error or f"sum = {result}")

node.job(crunch, 1000, done=show)
```

`node.submit_job` — это пул сервера, без привязки к ядру.

На обычной сборке CPython 3.14 и 3.15 у интерпретатора остаётся GIL. Пока lane исполняет чистый Python, другие колбэки Python ждут GIL, но сам worker сервера и Lua при этом не стоят: GIL им не нужен. Вызов в C или Mojo через ctypes GIL отпускает, и колбэк Python может идти параллельно. Свободная от GIL сборка (`--disable-gil`) снимает и это ограничение; `pyhost` нужно собрать тем же интерпретатором, с которым он запускается. Импорт расширения без слота free-threading снова включает GIL.

`node.core_info()` возвращает `index`, `processors`, `reserved`, `pinned`, `lane_id`.

## Mojo

Mojo не подменяет собой интерпретатор. У него нет встраиваемого runtime в том смысле, в каком встраивается CPython, а серверу нужен language host с `load` и `unload`. Mojo подключается библиотекой, которую вызывает уже запущенный Python, и этот вызов ставится на lane.

Два рабочих пути:

1. Расширение Python. В файле экспортируется только `PyInit_<имя>` с `abi("C")`, функции регистрируются через `PythonModuleBuilder`. Сборка:

    ```
    mojo build kernel.mojo --emit shared-lib -o kernel.pyd
    ```

    На Windows у файла должно быть расширение `.pyd`, на Linux `.so`. Загрузка из доверенного ресурса: `node.mojo.load_extension(path)`. Дальше `node.job(lambda: kernel.triangle(1000), done=show)`.

2. Если на `PYTHONPATH` есть пакет `mojo` из SDK, `node.mojo.enable_importer()` включает `mojo.importer`. Он сам вызывает `mojo build --emit shared-lib` и кладёт кэш в `__mojocache__`. Компилятор на машине с сервером для этого нужен. Готовый `.pyd` — нет.

3. Сырая библиотека с C ABI: `handle = node.mojo.load_native(path)`. Если в ней есть символ `initialize_runtime` с `abi("C")`, хост один раз вызывает его на lane (без `main` рантайм Mojo сам не стартует). `node.mojo.invoke(handle, "name", restype, argtypes, args, done=...)` выполняет вызов там же, ctypes на время вызова отпускает GIL.

Пример расширения лежит в `examples/kernel`. Mojo в поставку хоста не входит: без собранной библиотеки и без доверия к ресурсу загрузка не выполняется.

Недоверенный ресурс не получает `ctypes`, `subprocess`, `multiprocessing`, выход из процесса и запись окружения. Пока такой ресурс загружен, `open` ограничен его папкой и каталогом Python. Доверие задаётся в `server.toml`:

```toml
[resources]
trusted = ["kernel-py"]
```

`"*"` доверяет всем. Иначе `is_resource_trusted` равен нулю и песочница включена.

Доверенный ресурс ставит пакет в этот же интерпретатор прямым вызовом:

```python
os.system("pip install requests")
```

Хост забирает такую команду у оболочки и запускает `pip` внутри серверного Python, в том числе `py -m pip` и `python -m pip`. После удачной установки пакет можно импортировать сразу. Вызов ждёт окончания pip, и на это время колбэки Python стоят. Команда с `&&`, перенаправлением или другим текстом оболочки идёт в обычный `os.system` и в этот перехват не попадает. Недоверенному ресурсу `pip` и `os.system` закрыты: установка пакета исполняет чужой код.

## Ресурс

```toml
name = "hello-py"
type = "python"

[server]
main = "server/main.py"
```

Примеры: `examples/hello`, `examples/python-gate`, `examples/python-async`. Последний оставляет вердикт запроса синхронным, а приветствие и перекличку считает через `node.job`.

`node` уже лежит в глобалах скрипта. `node.on("playerJoined", fn)` выбирает builtin, vehicle-событие, вердикт или клиентское событие по имени. Вердикт отказывает через `False` или строку причины; исключение в таком обработчике тоже отказ, traceback пишется в лог. `node.on_builtin`, `node.on_vehicle`, `node.on_request` и `node.on_client` выбирают канал явно.

Остальные функции `NodeApi` доступны под своими именами из `sdk/node.h`. Строковые геттеры возвращают `str` или `None`. `node.json("get_world_snapshot_json")` ещё и разбирает JSON. `node.world()` и `node.metrics()` — короткие формы.

Имена, которые есть у запущенного сервера:

```python
names = sorted(name for name in dir(node) if not name.startswith("_"))
node.log_info(" ".join(names))
```

`help(node.get_player_name)` показывает сигнатуру обёртки. Что делает функция и с какой версии ABI она появилась, написано в `sdk/node.h` над её указателем и собрано в [API.md](API.md).

Пока идёт `load`, сервер сам приписывает регистрации ресурсу. Позже хост вызывает `set_resource_owner` вокруг подписки. `def unload(): ...` в скрипте вызывается перед выгрузкой.

## Сборка

Нужен CPython 3.14 или 3.15. Заголовок SDK уже в `sdk/node.h`. Интерпретатор и модуль должны быть одной сборки, обычной или free-threaded.

```
cmake -S . -B build -DPython_ROOT_DIR=C:\Python314
cmake --build build --config Release
```

На Windows модуль линкуется с динамическим CRT (`/MD`), как официальный Python. Рядом с сервером должны оказаться `pyhost.dll`, `python314.dll` (или `python315.dll` той же сборки) и каталог `nodemp` (или `NODEMP_HOST_ROOT` указывает на папку, внутри которой лежит `nodemp`). `libnode`-схема та же, что у `js-host`: библиотека интерпретатора рядом с исполняемым файлом сервера.

Если `node.h` вырос, заново сгенерируйте ctypes-слой:

```
py -3.14 tools/gen_abi.py
py -3.14 tools/gen_api_md.py
```

Поля `NodeApi` читаются по смещению. Генератор сохраняет порядок указателей из заголовка.

## Переменные

| Переменная | Смысл |
|---|---|
| `NODEMP_PYTHON_CORE` | Номер процессора, `last` (по умолчанию) или `off` |
| `NODEMP_PYTHON_RESERVE` | `0` — только приколоть lane, остальные потоки не двигать |
| `NODEMP_PYTHONHOME` | Префикс интерпретатора, если Python не находится сам |
| `NODEMP_PYTHONPATH` | Дополнительные каталоги в `sys.path`, через `;` на Windows и `:` на Linux |
| `NODEMP_HOST_ROOT` | Каталог, в котором лежит пакет `nodemp` |

Хост не ставит свои обработчики сигналов и не перенастраивает stdio сервера.
